# BTS Mini-App UI/UX PRD — 메인 화면 이후 (FlutterFlow Design Spec)

> **Purpose**: BTS 미니앱 메인 화면(캐릭터 선택 ~ 최종 일정) UI 시안 제작용 완전 명세서
> **Scope**: 랜딩(구현완료) + 세계지도(구현완료) 이후 → 캐릭터 선택부터 최종 일정까지
> **Target Tool**: FlutterFlow
> **Design Philosophy**: 미니멀 미학 · 이미지 = 버튼 · 텍스트 절제 · 직관적 · Apple HIG

---

## 1. 앱 흐름 (구현 완료 / 미완 구분)

```
[구현완료] BTS 랜딩 — OAuth + 생년월일
    ↓
[구현완료] 세계지도 — 34개 골드 핀 + 줌인 + 공연 카드
    ↓ 자동 전환
[미완 → 이 PRD 범위] ▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼

[Screen A] 캐릭터 선택
    7명 원형 배치 + "누구랑 여행하고 싶으세요?"
    캐릭터 탭 = Vibe 확정
    ↓
[Screen B] 장소 픽
    캐릭터 카드 중앙(주인공) + 8장소 원형 사진(주변, 부수)
    이미지 탭으로 2~8개 픽 → 게이지 바 채움
    ↓
[Screen C] 로딩 + BGM
    Vibe별 BGM 자동 재생 + 숏폼 생성 대기
    ↓
[Screen D] 숏폼 미리보기
    선택 장소 수 = 장면 수
    캐릭터가 각 장소에서 선정이유를 대사로
    Remotion 기반 영상
    ↓
[Screen E] 최종 일정
    타임라인 + 예산 요약 + 공유
```

## 2. 디자인 시스템

### 2-1. UX 핵심 원칙 (사용자 확정)
| 원칙 | 설명 |
|------|------|
| **이미지 = 버튼** | 모든 썸네일/아바타가 터치 반응. 별도 버튼 최소화. |
| **텍스트 절제** | 핵심 질문 1줄만. "이 바이브로 내 여행 만들기" 같은 국적불명 안내문 금지. |
| **기계적 버튼 절제** | CTA 버튼 남발 금지. 게이지 바 완성 = 자연스러운 진행. |
| **미니멀 미학** | 누가 봐도 설명 없이 직관적 선택 가능. |
| **이모지 완전 금지** | UI 어디에도 이모지 사용 안 함. |
| **풀스크린 몰입** | 상단/하단 시스템 UI 없음. 게임 시작 장면처럼. |

## 3. Screen A: 캐릭터 선택

### 시안 참조
> 사용자 제공 시안: 7명 캐릭터가 원형으로 둥글게 배치, 중앙에 "누구랑 여행하고 싶으세요?"
> 밝은 화이트 배경. 미니멀. 별도 버튼 없음.

### 와이어프레임
```
┌─────────────────────────────┐
│                             │
│         ○ 캐릭터1            │
│      ○            ○        │ ← 7명 원형 아바타
│    캐릭터7       캐릭터2     │    70~80px 지름
│                             │    360/7 = 51.4도 간격
│    ○                ○       │    중심 반지름 ~120px
│  캐릭터6          캐릭터3    │
│                             │
│      ○            ○        │
│    캐릭터5       캐릭터4     │
│                             │
│          누구랑              │ ← H1, 24px, Bold
│        여행하고              │    중앙 정렬, 3줄
│        싶으세요?             │
│                             │
└─────────────────────────────┘
```

### 구현 요소
| 요소 | 상세 |
|------|------|
| 배경 | 화이트 (#FFFFFF) |
| 7명 아바타 | 원형 PNG 이미지, 원형 마스크 |
| 배치 | 원형 (circle layout), 중심에서 반지름 ~120px |
| 질문 텍스트 | "누구랑 여행하고 싶으세요?" — 3줄 중앙, 이것만 |
| 인터랙션 | **아바타 탭 = 선택** (별도 버튼 없음) |
| 탭 반응 | 선택 아바타 scale(1.2) + 캐릭터별 그라디언트 테두리 |
| 비선택 | 나머지 6명 opacity 0.4 |
| 전환 | 0.5초 후 자동 Screen B 전환 |

## 4. Screen B: 장소 픽

### 시안 참조
> 사용자 제공 시안: "낭만주의자의 여정" 타이틀, 중앙에 캐릭터 카드 크게(주인공),
> 주변에 여행지 원형 사진들(부수). 하단 CTA 대신 게이지 바.
> **캐릭터가 주인공, 여행지가 부수** (현재 코드와 반대 — 교체 필요)

### 와이어프레임
```
┌─────────────────────────────┐
│                             │
│   {캐릭터 archetype}의 여정  │ ← H2, 20px
│   예: "낭만주의자의 여정"    │
│                             │
│      ○ 장소1    ○ 장소2     │ ← 원형 장소 사진 (60~70px)
│   ○ 장소8            ○ 장소3│    이미지 자체가 터치 반응
│          ┌──────────┐       │
│   ○ 장소7│          │○ 장소4│ ← 중앙: 캐릭터 카드 크게
│          │ 캐릭터   │       │    (~200x280px)
│   ○ 장소6│ 일러스트 │○ 장소5│    이름 + Vibe 태그
│          │          │       │
│          └──────────┘       │
│                             │
│  ════════════════════ 3/8   │ ← 프로그레시브 게이지 바
│                             │
└─────────────────────────────┘
```

### 구현 요소
| 요소 | 상세 |
|------|------|
| 배경 | 보라 그라디언트 (#1E1040 → #05050A) |
| 타이틀 | "{archetype}의 여정" — 한 줄만 |
| 중앙 캐릭터 | 카드형, 크게 (~200x280px), 캐릭터 일러스트 + 이름 |
| 주변 장소 | 8개 원형 사진 (60~70px), 원형 배치 |
| 장소 사진 | `imageUrl` from API (실제 장소 사진) |
| 장소 인터랙션 | **이미지 탭 = 선택/해제** (토글) |
| 선택 표시 | 그라디언트 테두리 + 체크 오버레이 |
| 미선택 | opacity 0.5 |
| 게이지 바 | 하단 고정, 선택 수/8 비율, "3/8" 텍스트 |
| 최소 선택 | 2개 이상 → 게이지 색상 변경 (진행 가능) |
| CTA 버튼 | **없음 또는 최소화** — 게이지 바 완성이 곧 진행 |
| 도시 선택 | 수평 칩 (34개 도시, 스크롤) |

### 장소 데이터 (API 응답)
| 필드 | 용도 |
|------|------|
| nameKo / nameEn | 장소명 (탭 시 표시) |
| imageUrl | 원형 썸네일 사진 |
| seedCategory | 카테고리 (attraction/healing/restaurant/hotspot/adventure) |
| priceEur | 가격 (탭 시 표시) |
| nubiReason | 선정 이유 → 숏폼 대사의 기반 |

### API
```
GET /api/bts/top-places?cityId={id}&memberId={characterId}
→ 8개 장소 반환 (Vibe weights로 매칭)
```

### 캐릭터별 장소 가중치 (seed_category 매칭)
| 캐릭터 | 1순위 (50%) | 2순위 (30%) | 3순위 (20%) |
|--------|------------|------------|------------|
| 컬렉터 | attraction | healing | restaurant |
| 로맨티스트 | attraction | healing | restaurant |
| 익스플로러 | hotspot | adventure | attraction |
| 챌린저 | adventure | restaurant | hotspot |
| 컴패니언 | healing | attraction | restaurant |
| 리차저 | healing | restaurant | attraction |
| 칠러 | healing | attraction | restaurant |

## 5. Screen C: 로딩 + BGM

### 와이어프레임
```
┌─────────────────────────────┐
│                             │
│                             │
│     ┌──────────────┐        │
│     │  네온 링     │        │ ← 보라 그라디언트 원형

## 6. Screen D: 숏폼 미리보기

### 핵심 규칙
> **사용자가 고른 장소 수 = 숏폼 장면 수**
> 4개 선택 → 4장면, 8개 선택 → 8장면
> 각 장면에서 선택한 캐릭터가 등장하여 선정이유를 대사로 말함

### 와이어프레임
```
┌─────────────────────────────┐
│                             │
│  [장소 사진 — 풀스크린]      │ ← Ken Burns 줌인 효과
│                             │
│      (캐릭터 애니메이션)     │ ← Remotion/Rive
│                             │
│  "석양 무렵 여기 오면        │ ← 1인칭 대사
│   파리가 금빛으로 물들어요"  │    (nubiReason 기반)
│                             │
│  ─── 스와이프 → 다음 장소 ───│
│                             │
└─────────────────────────────┘
```

### 구현 요소
| 요소 | 상세 |
|------|------|
| 레이아웃 | 풀스크린, 세로 |
| 배경 | 장소 실사 사진 (Ken Burns 줌인/패럴랙스) |
| 캐릭터 | Rive 애니메이션 또는 Remotion 영상 |
| 대사 | 1인칭 선정이유 (15자 내외) |
| BGM | Screen C에서 이어짐 (끊김 없음) |
| 전환 | 좌우 스와이프 → 다음 장면 |
| 장면 수 | = 사용자가 선택한 장소 수 |

### 1인칭 대사 생성 공식
```
캐릭터(성격) + nubiReason(선정이유) + Vibe
= 자연스러운 1인칭 대사 (15자 내외)
```

### 대사 예시 (같은 장소, 다른 캐릭터)
| 장소 | 로맨티스트 | 챌린저 | 칠러 |
|------|-----------|--------|------|
| 에펠탑 | "석양에 금빛으로 물드는 순간..." | "계단 674개 도전!" | "벤치에서 멍하니 올려다보기" |
| 센강 | "야경 크루즈에서 와인 한잔" | "카약 투어 있대!" | "강변 산책이면 충분해" |

### 기술
- **Remotion**: React 기반 영상 생성 (무료, 빠름)
- **Rive**: GPU 120fps 캐릭터 애니메이션 (~100KB/캐릭터)
- **MVP 대안**: 정적 이미지 + 텍스트 오버레이

## 7. Screen E: 최종 일정

### 와이어프레임
```
┌─────────────────────────────┐
│  [X]   나만의 방탄 투어  [>] │ ← 글래스 헤더 (닫기 + 공유)
├─────────────────────────────┤

### 슬롯 구조

- 숙박/항공 제외

## 10. 인터랙션 패턴

### 이미지 = 버튼
- 원형 아바타/장소 사진 탭 = 선택/해제
- 탭 시: scale(0.95) → scale(1.0) spring
- 선택: 캐릭터별 그라디언트 테두리
- 미선택: opacity 0.4~0.5

### 전환 애니메이션
| 전환 | 효과 |
|------|------|
| 세계지도 → Screen A | fade (0.4s) |
| Screen A → B | slide_from_right (선택 후 0.5초) |
| Screen B → C | fade (게이지 완성 시) |
| Screen C → D | fade (BGM 이어짐) |
| Screen D → E | slide_from_bottom |

### 게이지 바 (Screen B)
- 트랙: `rgba(255,255,255,0.1)`
- 채움: 보라 그라디언트 (`#A855F7 → #6C2DC7`)
- 2개 미만: 회색 (진행 불가)
- 2개 이상: 보라 (진행 가능)
- 8개: 자동 진행 또는 완료 표시
