## 1. 지구본 인트로 = 무엇인가

> **연출이다. 누르는 화면이 아니다.** 아미봉 인증창과 같은 성격.

| 성격 | 내용 |
|---|---|
| 하는 일 | 아미봉 인증화면에 나온 **그 도시**로 지구본을 돌려 정면에 세우고, 피켓을 키우며 멈춘다 |
| 사용자 조작 | **없음.** 3초 남짓 지나가므로 클릭을 받을 수 없다 |
| 피켓 | **임박 1도시 하나만.** 5개를 띄웠더니 겹쳐서 아무것도 안 보였다 |
| 도시 점·삼각뿔·동선 라인 | **없음.** 보여주는 도시가 하나라 표식이 불필요하고, 확대되면 피켓과 뒤엉켜 지저분했다 |
| 회전 | 처음부터 끝까지 **같은 속도**, **반 바퀴만**, 위아래는 **거의 옆에서 보는 각도** |
| 끝 | 최대 줌인 → 화면 전환 |

### 화면 구성 (파일 4개)

```
BTSWorldMapScreen.tsx   화면 틀 = 제목 + 인트로 타이머(3.5초) + 다음 화면 전환
  └ BTSGlobeIntro.tsx   지구본을 화면에 얹는 일만 = 웹은 iframe / 앱은 WebView
      └ bts-globe-html.ts  ★ 그림·움직임의 정본(HTML 문자열)
          └ cobe-inline.ts   지구본 라이브러리 본체(자동 생성 = 손대지 말 것)
```

**왜 HTML 인가** = cobe 는 브라우저 기술(WebGL)이라 iOS/안드로이드 화면에 그대로 못 올린다.
그래서 앱에서는 **WebView 안에서** 이 HTML 을 띄운다. 이 앱이 지도·장소검색에 이미 쓰는 방식이다(§16).
= **웹·앱이 같은 그림 1벌.** 옛것(웹만 지구본 / 앱은 SVG 평면지도 = 2벌)은 삭제 §19.

**`cobe-inline.ts` 다시 만들려면** = `node scripts/gen-cobe-inline.mjs`
(cobe 를 올릴 때마다 다시 돌린다. 인터넷 없이도 뜨게 하려고 본체를 파일에 끼워 넣는다.)

## 2. 미니앱 구조 = 메인앱이 **BTS 위로 스르륵 올라온다** (2026-07-31 확정)

> 사장님 SSOT: **BTS 팬에게는 미니앱이 주(主)**다. 하단 버튼을 누르면 메인앱이 **화면 절반까지 올라오고
> BTS 는 뒤에 살아 있어 터치까지 된다.** 손가락(마우스)으로 내리거나 X 로 닫을 수 있다 = **두 앱이 공존**.

### ✅ 정답 = 화면을 바꾸지 않고 **그 위에 얹는다** (SnapSheet)

**사장님이 2일 만에 찾아주신 답이다.** AI 는 계속 "화면 자체를 모달로 바꾸는" 길만 팠다.

> 사장님: *"BTS 에서 모달을 띄우는 것이 **메인앱 여정화면에서 쓰는 바텀시트 방식**으로 구현하면 될 것을…
> 마우스로 그 모달을 내릴 수도 있는 구조임"* / *"차이점은 **부모 화면**임"*

| 무엇 | 어디 |
|---|---|
| 창 본체 | `client/screens/bts/MainAppOverlay.tsx` **(신규)** |
| 부품 | `client/components/SnapSheet.tsx` = **전문가·AI의견이 이미 쓰던 것 그대로**(§16) |
| 부모 위치 | `client/App.tsx` 의 `NavigationContainer` **바로 밑** = 화면이 무엇이든 그 위에 뜬다 |
| 신호 | `MapToggleContext` 의 `requestMainApp(tab)` (로그인 팝업과 같은 형식) |
| 버튼 | `MainAppBottomTabBar.tsx` = 화면을 **안 바꾸고 신호만** 보냄 |

```
BTS 미니앱 화면 (그대로 살아 있음)
   └─ 그 위에 SnapSheet 으로 메인앱을 절반 높이로 얹음
        ├─ [여정]·[AI의견]·[전문가] → TripPlannerScreen
        └─ [프로필]                 → ProfileScreen
```

| 버튼 | 동작 | 판정 |
|---|---|---|
| 여정 | 창이 절반으로 올라옴 → 여정 입력화면 | ✅ 사장님 실증 |
| 프로필 | 창이 절반으로 올라옴 → **프로필 화면** | ✅ 사장님 실증 |
| AI 의견 | **여정 있을 때만** 활성 | ✅ |
| 전문가 검증 | **여정 있을 때만** 활성 | ✅ |
| Tripis(가이드) | 별도 미니앱 = 그대로 | ✅ |

### ⚠️ BTS 미니앱은 **`card`**(일반 화면)다 — `transparentModal` 아님

속이 비치는 모달은 **밑의 메인앱을 살려둔다.** 그런데 메인앱은 이제 위에 창으로 뜨므로,
밑에도 하나 살아 있으면 **여정 화면이 두 벌** 돌아 같은 전역 칸을 서로 지운다.

| 두 벌이 돌면 | 결과 |
|---|---|
| 갓 만들어진 쪽이 `null` 로 덮음 | **[AI의견]·[전문가]가 갑자기 회색** |
| 두 벌이 같은 신호를 구독 | **안 보이는 화면에서 크레딧 5가 빠짐**(§9 = 돈) |

⚠️ **지금은 증상이 안 보인다** — BTS 여정이 아직 저장되지 않아 전역 칸이 원래 비어 있기 때문
(계획서 D10·E2 가 그걸 채우는 단계). **D10 을 하는 순간 터진다.**
그래서 미리 `card` 로 바꿔 밑을 안 남기게 했다(2026-07-31). 겉모습 변화 0(사장님 실증).

### ⚠️ 창 안에 **네비게이터를 통째로 넣지 마라**

`MainTabNavigator`(탭 묶음)를 넣으면 화면 관리자가 두 벌이 되어 앱이 죽는다.
**화면 하나만** 넣는다(`TripPlannerScreen` 또는 `ProfileScreen`).

### ⚠️ 화면 밖에서 열리므로 **"내가 어디 소속이냐"를 묻는 코드가 터진다**

그 화면들이 원래 쓰던 훅이 창 안에서는 물어볼 곳이 없어 앱을 죽였다. 둘 다 **없으면 조용히 넘어가게** 고쳤다:

| 파일 | 무엇을 물었나 | 없을 때 |
|---|---|---|
| `useTripPlanner.ts` | `useRoute()` = 저장여정 복원 번호 | 없음(창으로 열 때는 복원할 여정이 없다) |
| `useProfile.ts` | `useHeaderHeight()`·`useBottomTabBarHeight()` = 여백 계산 | 0 (제목줄·탭이 없으니 여백도 없음) |

> 탭에서 평소처럼 열 때는 **옛날 그대로** 값을 받는다 = 기능 손상 0.

### AI 의견 · 전문가 = 여정이 있을 때만

둘 다 **"지금 보고 있는 여정"에 대해 묻는** 버튼이다. 여정이 없으면 물어볼 대상이 없다.
잠그지 않으면 **크레딧 5·10 이 헛되이 빠진다.** 메인앱 탭과 **같은 규칙 1벌**(`needsItinerary`).

⚠️ **아직 안 된 것**: BTS 여정은 아직 이 규칙에 안 걸린다. BTS 는 여정을 **자기 통**(`BTSContext.itinerary`)에만
담고 공용 통(`currentItinerary`)에는 안 담기 때문이다. **생성기 통합 때 함께 해야 한다** — 아래 §5 참조.

### 배지 조회는 합쳐서 나간다

`tabBadgeCount()` 를 부르는 곳이 4군데이고 하단 탭바가 BTS 화면 3개에도 붙어 있어,
화면을 한 번 움직이면 **같은 조회가 초당 5~8회** 몰려 나갔다(호출 1회당 요청 2개 = 역할+목록).
화면에 보이는 문제는 없지만 **DB 전송량 = 돈**이라 3초 안의 중복 호출은 먼저 나간 답을 함께 쓰게 했다.
실측 = 동시 8회 → **서버 1회**.
