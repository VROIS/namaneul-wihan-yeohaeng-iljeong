# 4. 로그인·계정 구조 — ✅ 확정 (2026-08-08)

## 4-1. 인증 = 소셜 3종만 신규 가입. 이메일창은 "이미 있는 내 계정 찾기"

```
신규 가입 ─── 구글 · 카카오 · 애플 3종만
                (제공자가 메일을 인증해 줌 = email_verified 실제 검사 중)

이메일창 ─── 가입 아님. 이미 있는 계정 찾아 들어가기
             관문 2개 = 메일 + 생년월일이 **둘 다** 맞아야 함
             ("생년월일은 비번처럼" 사장님 SSOT)
             없는 메일 → 404 "구글·카카오·애플로 시작해 주세요"
```

**업계 표준과의 관계**: 구글 Identity Platform 은 ①같은 메일이면 오류 내고 앱이 연결 ②인증수단마다 별도 계정 — **둘 다 표준 옵션**. 사장님 방식(②)은 표준에서 벗어나지 않는다.
공통 금지사항은 **"blind email matching"(메일만 보고 잇기)** 뿐이고, 이 앱은 소셜 3종에서 `email_verified` 를 이미 검사(`auth.ts:142/77`, `auth-apple.ts:94`).

## 12-5. ⚠️ 지도 배경 지명 = 알려진 한계(배포 후 실기기 재검증 필요)

**증상**: 구글 지도 SDK는 **그 페이지가 처음 로드되는 순간의 언어로 고정**되고, 이후 앱 안에서 언어를 바꿔도(재접속 없이) 이미 뜬 지도는 안 바뀜(구글 SDK 자체 설계 = 코드로 우회 불가, 캐시 문제 아님). 로컬 실증에서 실제 로드된 스크립트가 `intl/zh_ALL`(중국어 고정)인데 그 뒤 화면은 영어→스페인어→불어로 다 바뀌어도 지도만 중국어 그대로였음(직접 확인).

**배포 후 재검증 필요**(로컬 dev와 실제 배포/실기기 환경 차이 가능성 = §11 정합):

# 13. DB-only 여정 = 출발 깃발 복구(2026-08-13, Phase F 실사용 중 발견)

## 13-1. 증상·원인

Phase F(§12) 실사용 검증 중 사장님이 직접 발견: **DB-only로 생성한 파리 여정의 지도에 출발 깃발이 안 뜬다.** "Départ: ..." 텍스트 줄은 정상 표시되는데 지도(`ItineraryMap.tsx`)엔 마커가 없음.

git 이력 추적(`git log --all -G` 정규식 diff 검색) 결과 원인 확정: **2026-05-26 리팩터 커밋 `755409e`**("scenario.scenes 직접 사용 + 옛 슬롯 강제 폐기")가 DB-only 파이프라인(`ag4-db-finalize.ts`)에서 `accommodation` 필드 생성 코드를 삭제하면서, 그 뒤로 ~2.5개월간 DB-only로 생성된 모든 여정이 깃발 없이 나가고 있었음(MIX 파이프라인은 무관, 정상).

**사장님 핵심 통찰(실측 확인함)**: "DB-only"는 이미 발굴 완료된 도시의 기존 요소를 조합해 보여주는 것뿐 — 즉 도시를 확인하는 그 시점에 이미 도심 중심좌표까지 알고 있다는 뜻. 실제로 `ag2-gemini-recommender.ts:isCityReady()` → `city-resolver.ts:findCityUnified()`가 이미 `cities.latitude/longitude`를 조회해 갖고 있는데, `isCityReady()`가 이 값을 버리고 `{ready, cityId, cityName, count}`만 리턴하고 있었음. **새 DB 조회 불필요** — 이미 조회된 값을 리턴에 실어 보내기만 하면 되는 문제(최초 "새 쿼리 추가" 방안은 사장님 지적으로 폐기, §16 재조회 금지 정합).

## 13-3. ⚠️ 확정 방식 = 서버가 **이름을 안 만든다**(좌표만) — 사장님 판정으로 확정, 2026-08-13 §19

깃발에 필요한 건 **좌표뿐**인데 처음엔 MIX를 따라 `name: "{도시} 도심"`(한국어 고정 문자열)까지 같이 넣었다. 그 한 줄 때문에 그 문자열이 화면·저장·구글맵 딥링크로 새 나갔고, 그걸 막으려고 클라 4개 파일에 방어코드를 덧붙이는 연쇄가 일어났다(§22 판단3종이 매 라운드 새 구멍을 적발). 사장님 판정 = **오염원을 없애라**.

= `ag4-db-finalize.ts` 는 `accommodation: { day, coords }` 만 만든다. 이름이 없으므로 소비처의 **기존 분기**(`generalAccom?.name` 이 있을 때만 이름 노출)가 자동으로 번역 문구로 폴백한다 = **방어코드 0**.

| 문제점 | 해결책 | 사용자 관점 효과 |
|---|---|---|
| 서버가 만든 한국어 고정 문자열이 다국어 화면에 "Départ: Paris 도심"처럼 섞여 보임 | 서버가 그 이름을 **아예 안 만든다**(좌표만). 소비처 기존 분기가 번역 문구로 자동 폴백 | 어느 언어로 봐도 "Départ: Centre-ville de Paris"로 완전히 통일 |

**남는 차이 1건(사장님 판단 대기)**: `DailyTotal.tsx` 를 원본 복구한 결과, DB-only 드라이빙가이드 여정의 "바로가기" 딥링크 출발지가 도시명 텍스트(`origin=Paris`) 대신 도심좌표(`origin=48.8566,2.3522`)로 나간다. 구글맵은 둘 다 정상 처리하고 좌표가 더 정확하나, 그 파일 주석의 원래 의도(도시명 텍스트)와는 다르다. §3 보호 영역이라 임의로 안 건드림.
