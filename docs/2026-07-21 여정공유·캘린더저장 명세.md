## 기존 실측 (재발명 방지)
- **itineraries 테이블 = 이미 존재(29컬럼)**: id(integer)·user_id(varchar,NULL허용)·title·raw_data(jsonb=schedule_data 역할)·start_date·end_date·created_at 등 다 있음. **추가 필요 = `is_saved_by_user boolean` 1개뿐**(명세서 스키마 그대로 새 테이블 만들면 §16 위반).
- **여정 저장 = 이미 `/api/itineraries` 존재**(전문가탭이 사용, currentItineraryId). 공유·캘린더는 이 위에 얹음.
- **하단 탭 = `client/navigation/MainTabNavigator.tsx`**(일정·AI의견·전문가검증·프로필·Tripis 5탭). AI의견·전문가검증 = 최근 배포(커밋 c4290c7 등).
- **ics·공유 기능 = 없음**(신규 구현).
- **인증 = getUserData().token Bearer**(전문가탭 패턴, 비로그인=null=서버 401).

## 구현 범위 (우리 스택)
### A. 여정 공유 (Deep Link + 비회원 열람)
- 공유 라우트 `[GET] /shared/itinerary/:id` = 인증 미들웨어 예외(비회원 read-only 열람). id = 기존 integer id.
- 공유 링크 = `https://my-guide.replit.app/shared/itinerary/{id}` 클립보드 복사 + 카카오 공유.
- 비회원 진입 = read-only 렌더 + "나도 여정 만들기" 버튼 → 로그인/가입 유도.
- ⚠️ 저장·공유 실행 = 회원만(비회원 버튼 = 로그인 모달).

### B. 캘린더 저장 (.ics 우선)
- `generateICS(itinerary)` 유틸 = 여정 raw_data(날짜·시간·장소·메모) → iCalendar 표준 .ics. OAuth 0.
- 클라 = 다운로드/공유시트로 iOS·구글·아웃룩 등록.
- 확장: 구글 Calendar API(events.insert)·카카오 톡캘린더 = 나중 소셜로그인 사용자용(설계만 열어둠).

### C. is_saved_by_user 컬럼 추가 = 마이그레이션(기존 테이블 ALTER, 새 테이블 금지).

## 도미노 주의(회귀 위험)
- AI의견·전문가검증 탭 교체 = 그 기능 라우트·화면이 죽지 않게(삭제면 사장님 확인).
- itineraries 스키마 = raw_data·id(integer) 기존 형식 유지, 코드가 UUID 가정하면 안 됨.
- 인증 = 기존 Bearer 패턴 재사용(§16).
