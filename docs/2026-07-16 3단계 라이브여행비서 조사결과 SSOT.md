## 3. Gemini Live API — 사장님 질문 3개 직답 (공식문서 근거)

### ① "구글 라이브(같이 보고 들으며 실시간 답변)를 SDK로 가져올 수 있나?" → **조건부 예**

- ⚠️ **구글 공식 SDK 플랫폼 목록에 React Native 없음** = Swift / Kotlin / Java / Web / Dart / Unity 6개뿐. (https://firebase.google.com/docs/ai-logic/live-api)
- RN 경로 2가지, **둘 다 구글 1차 보증 아님**: ①`@react-native-firebase/ai` **v25.1.0**(Invertase = 제3자, 라이브 구현 실제 확인됨) ②WebSocket 직접.
- ⚠️ **Live API 전체가 Preview** = 구글 원문 *"isn't subject to any SLA or deprecation policy and could change in backwards-incompatible ways"*. 실제로 옛 라이브 모델 2개(`gemini-2.0-flash-live-001`, `gemini-live-2.5-flash-preview`)가 **2025-12-09 삭제됨**. (https://ai.google.dev/gemini-api/docs/deprecations)

### ② "프롬프트·설정으로 여행비서 하위메뉴를 우선 동작시킬 수 있나?" → **예 (확실)**
- ⑴ **systemInstruction** = 세션 열 때 "너는 Tripis 여행비서다, 한국어로, 우리 6기능 우선" 박아둠.
- ⑵ **function calling** = 6기능(통역/환율/SOS/메뉴판/교통/위치공유)을 함수로 선언 → AI 가 알아서 호출. 구글 공식 예제가 *"Turn on the lights please"* → `turn_on_the_lights` 자동호출 구조. **사장님 구상 = 구글 권장 설계와 일치.**
- ⚠️ 주의 3: ⓐ 도구 응답 자동처리 안 됨(구글 원문 *"You must handle tool responses manually"*) = 루프 자체 구현 ⓑ **구글 지도 도구는 Live API 미지원** = 교통·위치공유는 자체 함수로(구글 검색은 지원) ⓒ **systemInstruction 도 매 턴 재과금** = 짧게.
- (https://ai.google.dev/gemini-api/docs/live-api/tools)

### ③ "구글의 모듈화된 채팅창 UI를 그대로 가져올 수 있나? Wanderlog 가 그 방식인가?" → **아니오**
- 구글이 주는 것 = **화면 없는 통신 부품뿐**. 라이브 버튼·카메라뷰·채팅버블·마이크 파형 = **100% 자체 제작**.
- `live-api-web-console` = 스스로 *"공식 구글 제품 아닌 실험물"* 명시 + **웹 전용**.
- ⚠️ **RN 에는 웹의 자동 대화 헬퍼가 없음**: 파트너 문서 원문 *"Browser-only helpers such as startAudioConversation() and AudioConversationController are not available in React Native"* = 마이크 녹음→16kHz PCM→전송, AI 음성 24kHz 재생, 프레임 추출 **전부 수작업**.

⚠️ **§9 프로모션(가입 140크레딧 무료) 중에는 라이브를 열면 무료 사용자가 70분씩 태움** → **라이브만 프로모션 제외** 또는 프로모션 종료 후 오픈.

## 7. 🔀 갈림길 (사장님 2026-07-16 지시) — **A안 단순링크 vs B안 이식**

**사장님 원문**: *"단순링크로 처리한다면 2앱의 db가 다른데 사용자, 크래딧, 저장된것 등 필수 고유요소가 뭔지와 문제점을 적대적 관점에서 조사가 우선이다. 갈림길임."*

- **Tripis DB = Supabase** / **레거시 내손안에 가이드 DB = Neon** = **서로 다른 인스턴스**
- 쟁점: 사용자 식별 / 크레딧 잔액 / 저장물(가이드·여정) / 인증 토큰 / 결제
- 이미 아는 제약: 마스터플랜 최종 목표 = **한 앱(com.sonanie.guide)으로 신원교체** → 링크 방식이 그 목표와 어떻게 공존하는지가 핵심 질문.

### 7-1. 🔴🔴 **결론 = 갈림길이 A/B가 아니다. 이미 터진 지뢰가 먼저 있다** (오케스트레이터 직접 재검증 완료)

> ⚠️ 조사 4관점 중 3관점(A안 파괴·B안 파괴·제3의 길)은 **세션 한도로 미완** = 다음 세션에 재실행 필요.
> 완료된 1관점(고유요소 실측)의 치명 발견은 **오케스트레이터가 Supabase SQL + 코드로 직접 재검증함**(요원 주장 아님).

#### 실측 (2026-07-16, Supabase 직접 SELECT — 재검증됨)

| 형식 | 인원 | 크레딧 합계 | provider_id 없음 | birth_date 없음 | 이메일 보유 |
|---|---|---|---|---|---|
| **레거시형식**(`google_…`/`kakao_…`) | **64명** | **6,790** (≈€485어치) | **64/64** | **64/64** | 35 |
| uuid신규 | 77명 | 216 | 73 | 72 | 2 |

- 레거시 64명 소유: **가이드(사진+해설) 195개**(전체 207) / **크레딧 거래내역 121건(전부)**

#### 🔴 지뢰 = 이 64명은 **구글 로그인으로 못 찾는다**
`server/auth.ts:19-43` 실측 = 사용자를 딱 2가지로만 조회 → ①`getUserByProvider(provider, providerId)` ②`getUserByBirthDate(birthDate)` → 없으면 **③신규 생성**.
그런데 레거시 64명은 **provider_id·birth_date 둘 다 전원 NULL**.
→ **같은 구글 계정으로 로그인해도 못 찾음 → 새 uuid 계정 생성 → 크레딧 0, 보관함 텅 빔.** 옛 크레딧 6,790과 사진 195장은 DB에 남아있으나 **아무도 못 여는 유령**이 됨.
⚠️ **A안이든 B안이든 아무것도 안 해도 이미 깔려 있는 지뢰.**

#### 🟢 다행 = 살릴 열쇠는 존재 (코드가 안 쓸 뿐)
- 레거시 id = `google_<구글sub>` (레거시 `googleAuth.ts:65`) / Tripis 가 받는 값 = `tokenData.sub` (`auth.ts:111`) = **같은 값**
- → 접두어만 떼면 정확히 일치. **1회 백필**(`user_providers` 채우기)로 복구 가능. 이메일 경로로도 35/64 도달.
- ※ 사장님 계정(`google_103229431780116955364`)이 지금 **email-login(개발용 임시 경로)** 으로 들어오고 있어 당장은 정상 = **진짜 구글 OAuth 로 바꾸는 순간 터짐**.

#### 필수 고유요소 대조 (실측)
| 요소 | 레거시(Neon) | Tripis(Supabase) | 통하나 |
