## 단계별 상세 스펙 (후임 실행용)

### 1단계 DB — itineraries PK 복구 + expert_inquiries 신설
1. 선행 검사: `SELECT id, count(*) FROM itineraries GROUP BY id HAVING count(*)>1` — 중복 id 있으면 **중단·보고**(없어야 PK 가능. 현재 31행이라 문제 가능성 낮음)
2. 라이브: `ALTER TABLE itineraries ADD PRIMARY KEY (id);` (레포 schema.ts:137 serial PK와 동기 = §19-4)
3. 라이브: expert_inquiries CREATE (컬럼 = 작업트리 schema.ts 정의 그대로: id uuid PK / user_id FK users cascade / itinerary_id integer FK itineraries **ON DELETE SET NULL** / itinerary_data jsonb(여정+AI의견 스냅샷 박제) / user_message text NOT NULL / status varchar 'pending' / expert_id FK users / expert_reply text / is_read_by_user bool false / created_at / answered_at) + 인덱스 2개(user_id,created_at DESC)·(status,created_at DESC)
4. 검증: information_schema로 테이블·FK·인덱스 확인 + 테스트 INSERT/DELETE 롤백
- 사장님 계정 role='admin' 백필은 **로그인 연결(3단계) 후** 사장님 이메일로 지정(현재 is_admin=true 0명 실측)

### 2단계 BE — 문의 CRUD 4라우트 (신규 파일 server/expert-routes.ts, ~200줄)
- 등록: `server/routes.ts`의 registerRoutes 안에서 1줄 (bts-routes 등록 패턴 따름)
- 인증: 기존 Bearer 토큰(getUserId 패턴 — profileRoutes.ts:383 참조) + role 검사 미들웨어 `requireExpert`(users.role IN ('expert','admin'))
- 라우트 4개 (경로 = FE·admin대시보드 기존 규약 그대로):
  1. `POST /api/verification/request` — body {userId, itineraryData, userMessage, itineraryId?} → expert_inquiries INSERT. itineraryData에 AI의견 포함(FE가 rawData.verification 실어 보냄). ⚠️ 크레딧 차감은 8단계 전까지 없음
  2. `GET /api/verification/requests?userId=&status=` — 내 문의함(본인 것만) / expert·admin이면 전체. 응답에 안읽음수 포함
  3. `GET /api/verification/requests/:id` — 상세(본인 or expert·admin만). 사용자가 answered 상세 열람 시 is_read_by_user=true 갱신(배지 감소)
  4. `PATCH /api/verification/requests/:id` — requireExpert. body {status, expertReply(admin대시보드는 adminComment로 보냄 → 서버에서 매핑)} → 갱신 + status='answered'면 answered_at, **notificationService.createAndSendNotification({userId:질문자, type:'expert', title:'전문가 답변이 도착했습니다', message:답변 앞 80자, link:'/expert/'+id}) 1줄**
- status 값 통일: pending/in_review/**answered**/rejected — admin-dashboard.html:3344 VERIFICATION_STATUS_MAP의 'verified'를 'answered'로 교체(§19 한 벌, HTML 버튼 onclick 값도)
- ⚠️ notificationService.ts는 `import webpush from 'web-push'`가 최상단 → **npm i web-push 설치 필수**(미설치면 import 즉시 실패). VAPID 미설정 시 푸시 스킵 가드 추가: setVapidDetails는 env 키 있을 때만, sendPushToUser는 키 없으면 {success:false,sent:0,failed:0} 즉시 반환(알림 DB저장은 정상 진행 = 1차 인앱 완결, 2차에서 키만 넣으면 푸시 자동 활성)

### 3단계 BE — 로그인 백엔드 연결
