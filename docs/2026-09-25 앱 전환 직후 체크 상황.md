### 3-1. C2 상세 (옛 정본 1-1 과 2026-09-10 작업 기록 6절을 그대로 옮김)

- [ ] **베스트 여정 v2 + BTS 전용 분기 (한 묶음으로 간다)** — 2026-09-08 사장님·AI 확인 / **2026-09-10 사장님이 v2 의 뜻을 넓히심 = "사람이 벽돌을 옮기듯" 사용자가 나온 여정을 빼고·넣고·순서 바꾸고·시간 늘리면 그 상태에서 동선을 다시 만들어 준다. 뼈대 = 2026-09-10 기차역 방식(작업기록 맨 위)을 그대로 쓰고, 7동의 자리(큰 역)에 사용자가 고정한 곳이 들어간다.**

  **왜 한 묶음인가** = 둘 다 "사람이 정한 장소를 먼저 넣고 나머지를 기계가 채운다"는 같은 구조다. 주입구만 앞으로 옮기면 둘 다 풀린다.

  | | 사람이 정하는 것 | 기계가 하는 것 |
  |---|---|---|
  | v2 | 사장님이 장소 id 목록을 넣음(best_rank 보다 위) | 시간·동선·식당만 계산 |
  | BTS | 공연장 + 시각(고정) | 나머지 슬롯 |

  **지금 BTS 가 잘못된 지점** = `ag4-db-finalize.ts:373` `finalPlaceId` 블록. 여정을 **다 만든 뒤** 공연장을 `lastDay.places.push()` 로 뒤에 붙인다. 그래서 ① 시간 계산에 안 들어가고(마지막 볼거리가 19:00까지 차 있어도 그 뒤에 밀어넣음) ② 동선 계산에 안 들어가고(반대편이어도 마지막 슬롯) ③ 뼈대(AG1)가 슬롯 수를 셀 때 공연장을 안 센다. = 여정의 일부가 아니라 **나중에 얹은 스티커**.

  **고칠 방향** = `pipeline-best.ts` 처럼 분기를 따로 내고(`pipeline-bts.ts`), 주입을 **끝이 아니라 처음**에 한다. 뼈대를 만들 때부터 그 자리를 비워 두고 시작.

  **이미 있는 뼈대** = `types.ts:94 pinnedPlaceIds` + `route-local.ts:62` (핀은 반드시 포함). 새로 만드는 게 아니라 이 길을 넓히는 것.
