## 3. 지구본 = 사장님이 정한 성격 (중요 — 또 틀리지 말 것)

> **인트로 연출이다. 아미봉 인증창과 같은 성격.**
> · 사용자가 **누르는 화면이 아니다**(3초 남짓 지나감. 클릭 불가)
> · 하는 일 = 공연할 도시를 **정확히 보여주는 것**뿐
> · **피켓은 임박 1도시 하나만, 최대한 크게**(5개는 겹쳐서 안 보임)
> · 나머지 도시 **점·동선 라인 전부 제거**(효과 없고 지저분함)
> · 회전 속도는 **처음부터 끝까지 동일**, **반 바퀴만**, 위아래는 **거의 옆에서 보는 각도**
> · 마지막에 **최대 줌인 → 화면 전환**. 지구본 줌인이 약하면 **피켓이 확대되어 정지**해야 함

> · **피켓은 두 줄** = 도시명(위) / D-Day(아래). 한 줄로 붙이면 어디까지가 도시 이름인지 구분이 안 됨.
>   **아미봉 인증화면과 같은 짜임**(`BTSLandingScreen.tsx:363-364` 이 이미 두 줄) = 그것을 따라간 것.

### ⚠️ 이 화면에서 실제로 터진 사고 3가지 (다음 세션이 또 밟지 말 것)

1. **회전은 반드시 시간 기준.** 프레임마다 각도를 더하면 느린 기기에서 반 바퀴에 4.4초가 걸려
   **3.5초 인트로가 먼저 끝나 줌인이 아예 실행되지 않음**(실측한 실제 사고).
2. **배율은 곱해진다.** 피켓이 지구본 상자 **안**에 있어서 `지구본 2.6배 × 피켓 1.5배 = 3.9배`가 되어
   아이폰12(390px)에서 피켓 폭이 **1080px**(화면의 2.8배)로 터졌음.
   → 지금은 `PICKET_ZOOM / GLOBE_ZOOM` 으로 **역수 상쇄** = 상수에 적힌 숫자가 곧 눈에 보이는 배율.
   새 값을 넣을 땐 **두 배율이 곱해진다는 것**을 반드시 기억할 것.
3. **번들을 다시 굽지 않으면 옛 코드를 보게 됨.** `dist/` 는 정적 산출물이라 서버만 재시작해도 소용없음.
   `npx expo export --platform web` 후 **해시가 바뀌었는지 + 새 코드 문자열이 들어갔는지** 확인할 것.
   (이 사고로 "줌인이 안 된다"는 잘못된 결론을 한 번 냈음.)

### 서버 재시작 — ⚠️ `pkill` 쓰지 말 것
윈도우에서 `pkill -f "tsx server/index.ts"` 는 node 를 **못 죽임**.
옛 서버가 살아남아 **고친 코드가 아닌 것을 보고 "고쳤다"고 착각한 사고**가 있었음.
반드시 PID 로:
```powershell
netstat -ano | Select-String ":5056\s+.*LISTENING"   # PID 확인
Stop-Process -Id <PID> -Force
```
그리고 **지문으로 새 코드인지 확인**(예: `/api/cities/ready` 응답에 `country` 칸이 없으면 새 코드).

### Chrome DevTools 실증 — 인트로는 3.5초라 스크린샷 왕복(2초)보다 짧음
사진을 못 잡으므로 **추적기**를 쓸 것:
```js
// 200ms 마다 화면·배율을 기록 → 클릭 → 나중에 읽기
window.__t = []; setInterval(() => window.__t.push(document.title + '|' + ...), 200)
```
지구본 래퍼에 `data-globe-wrap="1"` 표식이 있음(측정용).
⚠️ 합성 클릭(`dispatchEvent`)은 RN Web 버튼에 **안 먹힘**. `mcp__...__click` 실제 클릭을 쓸 것.
