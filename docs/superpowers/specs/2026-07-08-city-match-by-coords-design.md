# 도시 동일성 = 좌표 우선 매칭 + 이름 유사어 검색 (중복도시·재발굴 유출 차단) — 설계

> 사장님 SSOT(2026-07-08): 도시 매칭을 키보드 언어(철자)로 하면 안 됨. **도시의 불변 컬럼 = 도시중심 좌표**로 동일성 판정. 언어(도시명)는 한국 초행 여행자가 정확 명칭을 모르니 **유사어 검색**처럼 관대하게.

## 문제 (실측 확정)

- **사고**: "본느" 입력 → 기존 Beaune(city 134, name="본", 좌표 47.025,4.8397, PSR 24곳)를 **못 찾고** 새 city 136 생성 → **21건 유료 재발굴(재과금)**.
- **근본**: `findCityUnified(input: string)` = **도시명 문자열만** 받음(좌표 안 받음). 매칭이 이름 정확일치/부분일치 위주.
  - 1단계 정확일치: `"본느" = "본"` 실패
  - 4단계 부분매칭: `cities.name LIKE '%입력%'` = `"본" LIKE '%본느%'` 실패 (방향 반대 = DB명이 입력보다 짧으면 못 잡음)
  - → 5단계 신규 INSERT = 중복 도시 + 재발굴
- **좌표는 formData.destinationCoords 에 있는데 findCityUnified 에 전달 안 함** → 불변키(좌표) 매칭 원천 불가.

## 설계 = 좌표 1순위 + 이름 유사어 2순위

### findCityUnified 시그니처 확장
```
findCityUnified(input: string, coords?: { lat: number; lng: number })
```
- `preloadCityData(formData.destination)` → `preloadCityData(formData.destination, formData.destinationCoords)` 로 좌표 전달(pipeline-v3:181).
- preloadCityData 도 coords 인자 추가해 findCityUnified 로 넘김.

### 매칭 순서 (신뢰도 순)
1. **좌표 근접 (불변, 최우선)** — coords 있으면 cities 에서 도시중심 좌표(cities.latitude/longitude 컬럼) 근접 도시 조회:
   - ⚠️ 사장님 SSOT 2026-07-08 = **반경 10m 오차 허용 = `ABS(lat - c.latitude) < 0.0001 AND ABS(lng - c.longitude) < 0.0001`** (= place 매칭 불변4 좌표10m와 동일 임계 = 일관). 근접 다수면 최근접 1개.
   - 찾으면 = **같은 도시 확정** (이름 무관) = 즉시 반환(재활용). Beaune 134·136 = 좌표 47.025000,4.839700 동일 = 즉시 134 매칭.
2. **이름 정확/별칭** (기존 1·2단계 유지) — 좌표 없거나 못 찾을 때.
3. **이름 유사어** (기존 3·4단계 강화):
   - 양방향 부분일치: `DB명 LIKE '%입력%' OR 입력 LIKE '%DB명%'` (지금은 한 방향만) → "본느"⊃"본" 잡음.
   - 정규화: 공백·조사·악센트 제거 후 비교.
4. **신규 INSERT** (기존 5단계) — 좌표도 이름도 모두 실패 = 진짜 최초. INSERT 시 coords 있으면 그 좌표 저장(다음 좌표매칭 가능).

### 핵심 원칙
- **좌표 있으면 이름이 뭐든 같은 좌표 = 같은 도시** = 중복 생성 0 (Beaune 사고 원천차단).
- **이름은 보조** = 좌표 없을 때만, 유사어로 관대하게.
- 신규 INSERT 는 **좌표+이름 다 실패한 진짜 최초만** = 유료 재발굴 최소화.
