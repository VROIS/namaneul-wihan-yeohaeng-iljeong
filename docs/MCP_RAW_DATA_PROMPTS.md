# MCP 로우데이터 수집용 프롬프트 (1단계 기본 DB + 2단계 한국인 인지도)

> **용도**: noapi-google-search-mcp 등 MCP로 API 비용 없이 도시별·카테고리별 장소 리스트 확보 후, 한국인 인지도까지 입혀 로우데이터 완성.  
> **변수**: `{도시}`, `{도시영문}`, `{카테고리}`, `{카테고리영문}`, `{장소목록}` 등은 자동화 시 치환.

---

## 카테고리 7개 (seed_category)

| 순서 | 한국어 | seed_category | 검색 시 영문 예시 |
|------|--------|----------------|-------------------|
| 1 | 명소 | attraction | museums, landmarks, monuments, tourist attractions |
| 2 | 맛집 | restaurant | restaurants, best food, cafes, dining |
| 3 | 힐링 | healing | parks, spas, wellness, quiet spots, nature |
| 4 | 모험 | adventure | theme parks, adventure activities, zoo, outdoor |
| 5 | 핫스팟 | hotspot | Instagram spots, popular places, trending |
| 6 | 역사 | heritage | history, historical sites, heritage |
| 7 | 쇼핑 | shopping | shopping |

> **테마 = 한 단어만 (사용자 SSOT)**: 세부 분류 (예: "역사 유적·NRHP·미션") 좁히면 Google/Gemini 검색 좁아짐 → 더 적은 곳 발견. 한 단어로 가야 더 많은 곳 발견. 선정 기준 = 3 조건 (구글 검색 + 리뷰 수 + 이미지 수).

## 1단계: 기본 DB (도시별·테마(카테고리)별 상위 30곳)

**목적**: 도시별·카테고리별 **30곳** 장소 리스트 확보.  
**30곳의 테마별 검색·순위 조건**은 아래 세 가지만 사용한다. (평점·인스타·매체 순위는 사용하지 않음.)

**범위 규칙(추가)**: 도시 중심 **반경 100km 내외**만 대상. 반경 밖 장소는 제외.

| 순서 | 조건 | 설명 |
|------|------|------|
| 1 | **구글 검색** | 구글 웹 검색 결과·노출량(검색량) 기준 |
| 2 | **구글 리뷰 수** | 구글 리뷰 **개수** 기준 (평점 아님) |
| 3 | **구글 이미지 수** | **순수 구글 이미지** 검색 결과 수 기준 (인스타 아님) |

즉, 1) 구글 검색 → 2) 구글 리뷰 수 → 3) 구글 이미지 수 순으로 반영해 상위 30곳을 선정한다.

- 각 카테고리별 **최대 30곳**, 순위·장소명(한국어)·장소명(영문)·구글검색 근거·구글리뷰수 근거·구글이미지수 근거·**imageUrl**·**priceEur**·출처.

## 2단계: 한국인 인지도 — 장소별 "한 줄 추천 이유(nubiReason)" + 근거 URL 검증

### 2단계 프롬프트 (장소 리스트 일괄)

```
당신은 장소별 "한 줄 추천 이유"를 수집하고 그 근거 URL을 검증하는 작업을 수행합니다.

## 규칙
- 아래 장소 수만큼 모두 채워야 하며, 빈 곳이 있으면 안 됩니다.
- 우선순위 1→5 순으로 검색해, 첫 번째로 확인된 출처를 사용합니다.

## 우선순위
1. 인스타그램 — 셀럽 20인 중 해당 장소 방문 게시물, 사진

## 절차
1단계: 각 장소에 대해 1→5 순으로 검색해 evidenceUrl을 찾고, nubiReason을 정리합니다.
2단계: 찾은 evidenceUrl 각각을 실제로 열어보고, "Sorry, this page isn't available"(인스타), "Video unavailable"(유튜브) 등이 없으면 verified:true로 표시합니다.
3단계: evidenceUrl은 마크다운 형식 없이 순수 URL만 반환합니다.

## 산출물
반드시 JSON 배열만 반환 (마크다운 코드블록 없이). 필드: placeName, sourceRank(1~5), sourceType(instagram|youtube|naver_blog|package|travel_app), nubiReason, evidenceUrl(순수 URL만), verified(검증 결과 boolean).
```

### 2단계 출력 형식 (JSON 배열)

- **필드**: `placeName`, `sourceRank`(1~5), `sourceType`(instagram | youtube | naver_blog | package | travel_app), `nubiReason`, `evidenceUrl`(순수 URL만, 마크다운 없음), `verified`(boolean).
- 예시: `[{"placeName":"에펠탑","sourceRank":1,"sourceType":"instagram","nubiReason":"리사 24년 5월 게시","evidenceUrl":"https://www.instagram.com/p/xxx","verified":true}, ...]`
- 1단계 기본 DB 테이블에 `source_rank`, `source_type`, `nubi_reason`, `evidence_url`, `evidence_verified` 컬럼을 붙여 저장하면 됨.

## 사용 순서 요약

1. **1단계**: 도시 목록 × 카테고리 7개 → 위 1-1~1-7 프롬프트로 MCP 호출 → **기본 DB** (도시·카테고리·순위·장소명·출처) 저장.
2. **2단계**: 기본 DB의 장소 리스트별로 위 2단계 프롬프트로 MCP 호출 → **nubiReason(한 줄 추천 이유)** + evidenceUrl 검증 결과 추가 저장.
3. 이 로우데이터를 기반으로 1차 Gemini 일정 생성·매칭 + 최종 일정에 반영.
