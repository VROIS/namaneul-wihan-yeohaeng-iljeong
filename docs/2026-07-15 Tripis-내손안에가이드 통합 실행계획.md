## Context (왜)

- **큰 그림**: 사장님이 정식 배포 중인 두 앱 — ①"내손안에 가이드"(`com.sonanie.guide`, Google Play+App Store 정식 심사 통과·운영중, RN WebView 셸+Vanilla JS 웹앱, DB=Neon) ②Tripis(`com.vibetrip.app`, 이 레포, 아직 스토어 미노출·개발중, DB=Supabase) — 를 하나로 합치려 함.
- **왜 이렇게 하는가**: 구글/애플 스토어 심사 과정이 길고 어려워 **다시 겪고 싶지 않음**. Tripis가 아직 한 번도 배포 안 됐으므로, Tripis를 "내손안에 가이드"의 **패키지ID/서명을 그대로 물려받아 업데이트로 위장 배포**하면 신규 심사 없이 교체 가능(백서 §16-1, "동일 package/bundleID로 업데이트 배포"). 오늘 세션에 Play 앱 서명 활성화(구글 서버가 진짜 키 보관) + 애플 계정 로그인 가능을 실측 확인 완료 — 기술적 전제조건 충족.
- **두 앱의 강점**: "내손안에 가이드" = 여행 **현장**(카메라로 찍으면 즉시 AI 해설), Tripis = 여행 **전** 계획(여정 생성). 백서의 최종 비전 = 이 둘을 합쳐 "여행 전+중"을 커버.
- **최신 기술 도입**: (1) 온디바이스 AI **Gemma 4 E2B**(구글, Apache 2.0, 2026-04-02 출시) — 사장님이 이미 속도·기능 직접 체험, "현존 우리앱 최적"으로 확정. (2) 영상 생성 **Gemini Omni Flash**(구글, 2026-05-19 I/O 발표, `gemini-omni-flash-preview`) — 여정 하루치(최대 8곳) 숏폼 미리보기(~60초)에 도입.
- **레거시에 이미 준비돼 있던 것**: `C:\Users\hzino\Desktop\내손안에 가이드\main-input-screen-rn-v1.0\` 폴더에 카메라 UI(WebView 비의존, 순수 RN)+온디바이스AI 네이티브 모듈 뼈대(`litert-bridge`, Kotlin+Swift, 추론코드는 주석처리된 스켈레톤)가 이미 만들어져 있었음(2026-04-05 "자비스AI" 시나리오 문서로 설계 확정). 이번 계획은 이걸 Tripis로 이식+완성하는 것.
