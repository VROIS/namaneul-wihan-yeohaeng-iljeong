# 로그인 화면 = iOS(Expo Go) vs AOS(APK)·웹 차이 = **원인 확정** (2026-07-15)

> **사장님 질문**: "iOS 앱 버전 로그인 화면 보관해. AOS(APK+웹) 화면이 달라서 이유를 모름. **누군가가 다시 만듦?**"
> **결론**: ❌ **아무도 다시 안 만듦. 같은 최신 코드.** 차이는 **Expo Go(QR 프리뷰)의 렌더링·에셋 로딩 실패** = 이미 2026-06-30 확정된 사안. **APK·웹이 정상.**

## 1. 두 화면 (2026-07-15 03:37 캡처)

| 항목 | **iOS = Replit Preview + QR = Expo Go** | **AOS(APK) · 웹** |
|---|---|---|
| 로고(`tripis-mark.png` 120×120) | ❌ **안 보임**(자리만 비어 있음) | ✅ **보임**(파란 날개 마크) |
| 배경 | 보라 그라데이션처럼 보임 | 흰색 |

| 로그인 없이 둘러보기 | (캡처 잘림) | ✅ 보임 |

## 2. "다시 만든 것 아님" = 증거

- **`개발용 이메일 로그인` = 커밋 `f339881` (2026-07-14 23:59) 에서 추가** = 어제 밤 작업.
- 그게 **iOS 화면에도 있음** → **iOS 도 최신 코드를 돌리는 중**. 옛 버전이면 존재 불가.
- **배경 그라데이션 색 = 옛 코드·지금 코드 완전 동일** (`["rgba(139, 92, 246, 0.05)", "#FFFFFF"]`, 50c4cb3^ 과 HEAD 비교) → 배경 차이는 **코드 버전 문제 아님**.
- ⇒ **누군가 다시 만든 것 아님 = 같은 코드, 다른 실행 환경.**

## 3. 원인 = Expo Go (이 프로젝트에서 이미 은퇴 결론)

메모리 [[reference_expogo_deprecated_apk_ota_normal]] (2026-06-30 사장님 확정):
> "JSBigFileString 크래시 = **Expo Go(QR접속)만의 문제**(프로젝트가 커져서 큰 번들 로딩 실패)지 **실사용 APK+OTA 는 정상**. Expo Go 는 사실상 은퇴."

- Expo Go = 번들·에셋을 Metro 에서 실시간 수신 → 프로젝트가 커서 **117KB 로고 PNG 등 에셋 로딩 실패** → 자리만 남고 이미지 안 뜸.
- APK·웹 = 에셋이 빌드에 포함 → 로고 정상.
- ⇒ **iOS 화면이 이상한 게 아니라 Expo Go 가 이상한 것.** 코드 수정 대상 아님.

## 4. 코드는 정상 (확인 완료)

- `LoginScreen.tsx:409-413` = `<Image source={require("../../assets/images/tripis-mark.png")} style={styles.tripisMark} resizeMode="contain" />`
- `styles.tripisMark` (:850) = `{ height:120, width:120, marginBottom:24 }` = **크기 명시** = 크기 누락 아님
- `assets/images/tripis-mark.png` = **존재**(117KB, 2026-05-17). 같은 파일이 `app.json` 의 `icon` 으로도 사용.
- ⇒ 웹·AOS 에서 정상 표시되므로 **코드·에셋 모두 정상**.

## 5. 결론 = 앞으로 iOS 확인 방법

| 경로 | 신뢰도 |
|---|---|
| **Expo Go(QR·Replit Preview Mobile App)** | ❌ **신뢰 불가** = 은퇴(2026-06-30). 로고 안 뜸 등은 여기서만 발생 |
| **APK(안드로이드) + Chrome 모바일 에뮬** | ✅ 표준 테스트 경로 [[reference_android_repro_chrome_emulation]] |

> **조치 불필요**(코드 정상). iOS 화면 확인이 꼭 필요하면 Expo Go 말고 **실기기 배포본**으로.
