# Cloudflare 이전 실행계획 — 창고(R2) 우선 → 준비 → DB 다이어트 → 서버 이사

> 2026-08-06 사장님 승인 확정. **여러 세션에 걸친 장기 실행계획 — 이 파일이 정본(SSOT).**
> 모든 진행상황 갱신·단계 완료 체크는 이 파일에서. [`2026-07-15 Tripis-내손안에가이드 통합 실행계획.md`](2026-07-15%20Tripis-내손안에가이드%20통합%20실행계획.md)(가이드탭·숏폼·신원교체)와 별개 트랙, 서로 링크.
> 작성 원칙(사장님 지시): **비개발자도 이해되게** — 전문용어는 괄호 풀이 + "이렇게 하면 → 이게 해결되고 → 뭐가 좋아진다" 체감 관점.

## 왜 하는가 (지금의 문제 3가지)

| 지금의 문제 | 이사하면 |
|---|---|
| Replit(지금 서버를 돌려주는 회사)에 매달 ~€100 나감 | 매달 **$5**로 줄어듦 = 연 €1,200 이상 절약 |
| Supabase(지금 DB·파일 창고 회사) 무료 한도가 꽉 참 — 특히 **파일 창고 0.9/1GB = 새 영상을 1~2개밖에 못 만드는 상태** | 창고를 Cloudflare R2(파일 창고 서비스, 10GB 무료·전송비 영구 무료)로 옮겨 **영상 제작을 다시 마음껏** 할 수 있음 |
| 서버가 한 곳에만 있어 멀리서 접속하면 느림 | Cloudflare는 전세계 분산망 — **사진·영상·화면이 사용자와 가까운 곳에서 나가 앱이 빨라짐** |

추가 목표: **클로드(AI)가 DB 관리 + 유지보수 + 배포까지 직접 다 할 수 있는 구조** 완성(git push 한 번이면 자동 배포).

## 사장님 확정사항 (2026-08-06 단답 확정)

1. 이 문서가 정본(새 문서, 2026-07-15 문서와 상호 링크).
2. **순서 = 파일 창고 이전이 1순위**(꽉 찬 창고부터). 그다음 준비 → DB 다이어트 → 서버 이사. 한 번에 다 옮기기(빅뱅) 금지.
3. **DB는 포스트그레스 유지(Supabase에 그대로).** 처음 검토한 Cloudflare D1은 조사 결과 포스트그레스와 **다른 계열(SQLite)** — 옮기면 DB 안 자동 안전장치(중복차단·자동랭킹 트리거 = 헌법 §14)를 다시 만들어야 하고 €1000 자산이 위험 → **제외 확정**. DB를 안 옮기니 데이터 이사 자체가 없어져 계획이 훨씬 안전·가벼움.
4. 도메인(자체 주소) 구매 여부 = 서버 이사 시점(4단계)에 검토.

## 이사 후 최종 모습

| 무엇이 | 어디로 | 사장님 체감 |
|---|---|---|
| 사진·영상·raw(외부호출 원본) | Cloudflare **R2** 버킷 `tripis-videos` (폴더 4개: place-images/ itinerary-videos/ raw-responses/ guides/) | 창고 걱정 소멸, 사진·영상 더 빨리 뜸, 전송비 0 |
| 앱 화면(웹) | Cloudflare 정적 제공(무료·무제한) | 화면 로딩 빨라짐 |
| API 서버(로그인·여정생성 등 두뇌) | Cloudflare **Worker**(서버 프로그램을 전세계 분산망에서 돌려주는 서비스)로 새로 작성 | Replit 요금 소멸, 응답 빨라짐 |
| **DB(여정·장소·회원·크레딧 장부)** | **Supabase에 그대로(안 옮김)** | 이사 위험 0. Worker에서는 Hyperdrive(멀리 있는 DB를 가깝게 연결해주는 Cloudflare 장치)로 접속 |
| 일별 영상 만들기(2~3분 작업) | Cloudflare Workflows(오래 걸리는 작업을 기다렸다 이어주는 장치) + 영상 이어붙이기(ffmpeg)만 작은 임시 작업방(컨테이너) | 지금과 똑같이 동작, $5 안에 포함 |
| 환율 자동 갱신(하루 3번) | Cloudflare 타이머(Cron) | 동일 |
| 푸시 알림 | Workers용 라이브러리로 교체(열쇠·구독 그대로) | 변화 없음 |
| 배포 | **git push 한 번 → 자동 빌드·배포**(Workers Builds, 무료 CI) | 사장님 습관 그대로 |
| 클로드의 DB 관리 | 지금처럼 직접 접속(무변경) | 목표 충족 |

**중간 혼합 운영(사장님 질문 확인)**: 사진·영상 주소는 DB에 글자(URL)로 적혀 있을 뿐 → 파일을 R2로 옮기고 주소만 바꾸면 **앱은 R2에서 미디어를 불러오면서 DB·서버는 Supabase·Replit에 그대로** 있어도 됨. 1단계가 정확히 이 상태를 만든다(2026-08-04 영상 8.41MB R2 업로드·재생 실증 완료).

**이걸 하면**: 매달 €100 나가던 Replit을 해지하고, 서버가 분산망에서 돌아 더 빠르고 더 싸게($5/월) 된다.

- [ ] **이사 전 안전장치 6가지 먼저 등록**(4월 Koyeb→Replit 이사 때 로그인 끊김 사고 재발 방지 = 옛·새 주소 **양쪽 다** 미리 등록): 구글·카카오·애플 로그인 콘솔 / Stripe 결제 알림창구(웹훅) 옛·새 동시 활성 / API 열쇠들 / 푸시 알림 열쇠. **6가지 끝나기 전엔 전환 금지**
- [ ] 도메인 결정(사장님, 여기서): 권고 = 자체 주소 구매(연 ~$10, 한 번 사두면 이후 어떤 이사에도 재등록 불필요)
- [ ] 전환: 연습 주소에서 5가지 실연 검증(구글/카카오 로그인·여정 생성·영상 1건·시험 결제·푸시 1건) → 통과 시 앱 주소만 교체. **DB는 안 움직임 = 데이터 이사 없음.** 문제 시 주소만 되돌리면 즉시 원상복구
- [ ] 철거(안정 1~2주 후 사장님 승인 시): Replit 해지, 옛 서버 코드·설정 완전 삭제(§19), Supabase는 DB만 남김, 헌법 §13(Replit 설정) 새 배포 방식으로 개정(사장님 승인)
