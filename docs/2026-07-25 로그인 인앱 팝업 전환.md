### 알려진 제약 (기록, §11 정직)

- **OTA 가 APK 보다 먼저 도착하는 구간**: push 하면 EAS Update(수분)가 새 JS 를 기존 APK 에 먼저 내려보내고, 새 APK 는 수십 분 걸림. 그 사이 **기존 APK 에서 카카오 버튼을 누르면 카카오톡에서 앱으로 못 돌아옴**(복귀용 액티비티가 옛 APK 매니페스트에 없음). → **새 APK 설치 후에 앱 로그인 테스트.**
- **클라우드 EAS 빌드(iOS·production)에는 열쇠가 안 들어감**: `eas.json` 에 `env` 블록이 없고, 이번에 만든 사전검사는 GitHub Actions(로컬 안드로이드 빌드)만 지킴. → 아이폰 진행 시 **EAS 대시보드 환경변수**에 같은 열쇠를 넣어야 함.
- **BTSLandingScreen 의 죽은 OAuth 블록**(§19 정리 대상, 기존부터 존재): `handleLogin` 이 인증 없이 통과시켜 구글 훅·응답 useEffect·미사용 import 8건이 도달 불가 상태. **보호주석 구역이라 사장님 승인 후 삭제**.
- 🔴 **실증 중 발견 = `/api/auth/email-login` 이 로그인 통계·생년월일을 저장하지 않음**(기존 동작, 이번 변경과 무관 — git 로 확인). 실측: 이메일 로그인 200 성공인데 DB `login_count` 0 그대로, `last_login` null 그대로, 팝업에서 넣은 생년월일 `1967-06-03` 도 저장 안 됨(기존 `1990-01-01` 유지). 소셜(구글·카카오) 경로는 `findOrCreateUser` 를 타서 정상 저장·갱신됨(위 DB 실증 ①~④). → **이메일 로그인은 "개발용 우회"라 그런 것인지, 통계·생년월일도 저장해야 하는지 사장님 판단 필요.**
- **OnboardingScreen.tsx:115 `handleSocialLogin`**(§19·§20 정리 대상, 기존부터 존재): 서버 호출 0으로 `kakao_<시각>` 같은 **가짜 id 를 지어내 로그인 처리**함 = 이번에 지운 우회로와 같은 종류(오히려 더 나쁨). 화면으로 이동하는 코드가 없어 실제로는 도달 불가라 이번엔 안 건드림. **사장님 승인 시 같이 삭제**.
