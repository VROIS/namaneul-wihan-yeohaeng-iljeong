1. 철칙 (추가편 범위 행의 판정 줄에 적용한 번호를 적는다)
대명제: "이 가격에 여행자는 이곳에서 이 체험이 가능한가?" 행마다 이 질문의 답을 한 줄로 적는다(체험_한줄). 아래 모든 규칙은 이 답을 정하는 수단이다.
 1. 대상 = 도시 카드 23곳의 손님상 행뿐.
 2. 분류는 우리 7개(유적·포토스팟·즐길거리·모험·힐링·쇼핑·식당)뿐이다. 호텔은 분류도 태그도 아니고 장소 이름일 뿐인 표식이다. 우리 분류표가 구글 분류표보다 먼저다. 우리 분류에는 카페가 없다 = 카페·바·펍은 식당이다.
 3. 상호(업체명)가 식당·카페·바·칵테일 바·와인 바·펍·커피숍·베이커리·티룸이면 그 행은 식당이다.
 4. 구글 종류 글자 하나·표 한 줄로 결론 내지 않는다. 문맥(요약·묘사·후기·사진)으로 정한다. 호텔 객실 요금은 가격이 아니다.
 5. 호텔·시설은 그 행(CID)에서 사람들이 무엇을 하는가 하나로 우리 분류에 맞춘다: 식사·술이 조금이라도 있으면 식당 · 스파·사우나·데이유즈 = 힐링 · 전망 테라스·야경 = 포토스팟 주 + 식당 태그 · 숙박뿐 = 격리(hotel). 여럿이면 가장 많이 하는 일이 대표이고 나머지는 태그다. 안에 고유 이름을 가진 가게가 따로 등록돼 있으면 고유 이름이 더 정확한 답이다(철칙 6). 고유 이름이 없으면 호텔 이름을 쓴다.
 6. 한 행은 한 업체다. 안의 가게를 찾는 길은 세 번이다: ① "At this place" View all ② 구글 맵 검색창에 "<이름> restaurant"·"<이름> bar"·"<이름> cafe" ③ 구글 검색 "<이름> 안에 레스토랑·바". 세 번을 다 하고도 별도 등록이 없을 때만 "별도 등록 없음"이다. 같은 건물·같은 주소에 별도 등록(자기 CID)이 있으면 새 행 후보로 낸다(후기가 적어도 낸다). 호텔 행은 철칙 5로 따로 정한다.
 7. 쇼핑몰·시장·백화점·마트 = 이름이 식당 상호가 아니면 쇼핑(식당 태그 제거). 동네·거리 = 포토스팟 또는 쇼핑이고 식당 태그를 붙이지 않는다. 탑·수도원·박물관·공원 같은 시설도 그 행 자체가 먹고 마시는 곳이 아니면 식당 태그를 뗀다. 행 이름이 곧 먹고 마시는 곳(바·펍·비어 가든·카페·식사가 되는 공연장)이면 식당 태그를 유지한다. 이름에 식당 상호가 든 루프탑·옥상 바·카페는 식당 주분류 + 포토스팟 태그다. 상호 없는 루프탑·옥상·전망대는 포토스팟 주(먹고 마실 수 있으면 식당 태그)다. 와이너리·샴페인 하우스는 시음·견학 체험이라 즐길거리, 도심 와인 바는 식당, 포도밭은 힐링, 와인 가게는 쇼핑이다. 이름에 식당이 든 와이너리는 식당 주분류 + 즐길거리 태그다.
 8. 식당은 가격 칸을 반드시 채운다. 순서는 ① 구글 맵 페이지 머리줄 ② 공식 사이트 ③ 구글 검색 단서. 머리줄 값이 있으면 그 값(범위는 상한, "X+"는 X)이 이긴다 — 검색 값이 더 높아도 머리줄이 이긴다. 높은 값을 고르는 것은 같은 층 안(검색 단서끼리)에서만이다. 세 칸을 모두 적는다(없으면 "없음"). 셋 다 없으면 구글 검색에 "이 식당 1인당 식대가 보통 얼마인가"를 묻는다. 유로가 아니면 환율로 유로 환산(소수 첫째 자리 반올림).
 9. 후기 수는 보되 후기 수로 거르지 않는다. 별점은 쓰지 않는다. 뺄 것은 폐업·임시 휴업·장소 아님·다른 도시뿐이다.
10. 요약·묘사·분류는 한 짝이다(분류를 바꾸면 글도 맞춘다). 글 = 요약 25자 · 묘사 35자 · 코믹, 사실 100% 또는 상상 가능, 재미 우선, 안내문 금지.
11. 확신 눈금: "확실"은 행의 칸이 구글 로그·제미니 로그와 짝이 맞거나, 연 페이지로 의심이 풀렸을 때 쓴다. 로그로도 페이지로도 답이 안 나오면 "애매"다. 책임자는 의심 한 줄이 있는 "애매"만 다시 연다.
12. 다른 가게 혼동: 요약·묘사가 말하는 업종(예: 식당)과 구글 페이지·후기의 실제 업종(예: 꽃가게·식품점·사무실)이 완전히 다르면 글과 분류가 통째로 틀린 행이다 → 처리 "삭제", 확신 "애매". 분류만 바꿔 살리지 않는다. 단 실제 가게가 그 자체로 여행자가 찾아가는 곳(시장·유명 상점가·박물관급)이면 삭제 대신 주분류변경 + 글 새로 쓰기, 확신 "애매".
애매할 때 순서: ① 요약·묘사·로그 → ② 구글 검색(브라우저에서 google.com)으로 힌트 → ③ 페이지 여는 규칙 4번에 걸릴 때만 힌트를 들고 구글 맵 페이지를 직접 열어 읽는다(끝까지 스크롤 · "At this place" View all · 후기 최신 순 · 후기 주제 칩 · 호텔 위젯·사진). 도구에 맡겨 걸러 낸 조각만 받아 쓰지 않는다.
삼중 검증: ① 일꾼이 판정하고 확신(확실/애매)을 적는다 → ② 최종 검수 책임자가 의심 한 줄이 있는 애매만 다시 연다 → ③ 그래도 애매하면 어사이드가 사실을 모으고 사장님이 결정한다. 모르면 "애매"로 올린다. 찍지 않는다.

2. 확인 문제 16개 — 네 조번호 몫 4개만 푼다(정답은 이 글 안에 있다)

Q4 애매할 때 판단 순서는?
Q5 후기 수·별점이 낮은 식당은 빼는가?
Q6 식당 가격 단서가 없으면 어떻게 하는가?
Q7 호텔 안의 식당이 창고에 이미 별도 행(같은 CID)으로 있으면 새 행을 또 내는가?
Q8 쇼핑몰·시장·백화점 안에 식당이 있지만 행 이름이 식당 상호가 아니면?
Q9 새 행을 만들기 전에 확인할 것 3가지는?
Q10 CID 는 구글 맵 주소창 어디서 읽는가?
Q11 후기는 어떤 순서로 읽는가?

Q13 "확실"을 쓸 수 있는 조건은?
Q14 요약은 식당인데 구글 페이지·후기가 꽃가게·식품점이면?
Q15 호텔·시설 안의 가게를 찾는 세 번은 무엇인가? 언제 "별도 등록 없음"이라 말하나?
Q16 페이지 머리줄 가격이 있는데 검색 값이 더 높으면 어느 쪽을 쓰나?
(정답 요지: Q1 안에 식당·스파·전망이 하나도 없고 글·후기가 숙박뿐일 때 · Q2 아니오, 호텔은 표식이다. 그 행(CID)에서 사람들이 하는 일로 우리 7개 분류에 맞춘다 · Q3 아니오, 우리 분류표 → 상호 → 문맥 · Q4 요약·묘사·로그 → 구글 검색 → 페이지 여는 규칙 4번에 걸릴 때만 구글 맵 페이지 · Q5 아니오, 폐업·임시 휴업·장소 아님·다른 도시만 뺀다 · Q6 구글 검색에 1인당 식대를 묻는다, 식당은 가격을 반드시 채운다 · Q7 아니오, 중복 금지(창고 중복은 최종 검수 책임자가 CID 로 확인) · Q8 쇼핑, 식당 태그 제거 · Q9 CID 로 창고 중복 · 영구·임시 폐업 아님 · 구글 맵에 별도 등록 있음 · Q10 "!1s0x…:0x…" 의 콜론 뒤 16진수를 10진수로, 호텔 안 가게를 눌러 열면 두 번째 "!1s" · Q11 최신 순 · Q12 "애매"로 올리고 찍지 않는다 · Q13 행의 칸이 로그와 짝이 맞거나 연 페이지로 의심이 풀렸을 때, 로그로도 페이지로도 답이 안 나오면 애매 · Q14 삭제 후보 + 애매(분류만 바꿔 살리지 않음, 실제 가게가 여행자가 찾아가는 곳이면 주분류변경 + 글 새로 쓰기 + 애매) · Q15 At this place View all / 맵 검색 "<이름> restaurant·bar·cafe" / 구글 검색, 세 번 다 하고도 없을 때만 · Q16 머리줄(상한) 값, 높은 값 고르기는 검색 단서끼리일 때만)

3. 한 행을 판정하는 절차 (추가편 범위 행)
S1 요약·묘사를 읽고 "안에서 하는 일"을 한 가지로 적는다: 식사·술 / 스파 / 전망 / 숙박뿐 / 글 없음. (칸: 글_단서)
S2 (2026-10-15 사장님) 안의 가게 찾기 = 호텔·시설(탑·몰·호텔·공원) 행은 먼저 구글 맵 검색창에 "<이름> restaurant", "<이름> bar", "<이름> cafe", "<이름> spa" 를 쳐서 나온 결과 이름과 주소를 적는다(같은 건물·같은 주소인 것만). (칸: 맵검색) 맵에서 못 찾았을 때만 구글 검색(브라우저로 https://www.google.com/search?q=…&hl=ko)을 한 번 한다: "<이름> 안에 레스토랑·바·스파". 식당 행은 머리줄 가격이 없을 때만 구글 검색을 한 번 한다: "<이름> 1인당 식대". 질문과 받은 힌트를 적는다. 검색을 안 했으면 이유를 적는다(예 "안 함: 맵에서 찾음", "안 함: 머리줄 가격 있음"). (칸: 검색 = 질문·힌트 목록)
S3 페이지 여는 규칙 4번에 걸릴 때만 구글 맵 페이지를 연다(안 걸리면 S4 로 간다): https://maps.google.com/?cid={CID}&hl=en . 아래를 전부 읽고 적는다. (칸: 페이지)
   - 끝까지 스크롤했는가 · "At this place" 안의 가게 이름(분류·후기 수) 전부(View all 이 있으면 눌러서 전부)
   - 후기 탭 → 정렬을 Newest(최신 순)로 → 최신 5개의 글 요지(작성 시각 글자 포함)와 각 후기의 종류(숙박/전망·테라스/식사·술/스파) · 후기 주제 칩 상위("OO, mentioned in N reviews")
   - 호텔 위젯(예약·요금)이 붙어 있는가 · 사진이 호텔인가 · Menu 탭 · 영업 상태(Permanently / Temporarily closed) · 머리줄 가격(예: €20–30)
S4 판정한다: 아래 4번 처리 방침표에서 해당하는 번호를 고르고, 철칙 번호를 적고, 처리를 하나 고른다. (칸: 방침, 철칙, 체험_한줄, 처리)
   처리 = 격리유지 / 식당태그제거 / 식당태그유지 / 주분류변경(→새 분류와 태그를 fix 에 적는다) / 삭제 / 그대로
S5 분류가 바뀌거나 글이 구글과 다르면 요약·묘사를 짝 맞춰 다시 쓴다(철칙 10). (칸: 짝확인)
S6 식당이면 가격을 채운다(철칙 8). (칸: 가격, 가격근거 = 머리줄·공식·검색·채택 네 칸)
확신 = 확실 또는 애매(철칙 11). (칸: 업종일치 = 요약업종·페이지업종·후기업종·일치)

4. 처리 방침표 — 상황마다 처리가 정해져 있다. 예는 가상 사례다
방침 1 호텔·시설 행 · 후기·묘사에 식사·술이 있다 → 주분류변경: 식당(호텔 이름 그대로). 스파·사우나·데이유즈가 있다 → 주분류변경: 힐링. 전망 테라스·야경이 있다 → 주분류변경: 포토스팟 주 + 식당 태그. 여럿이면 가장 많이 하는 일이 대표이고 나머지는 태그.
방침 2 호텔 행 · 묘사도 후기도 숙박 이야기뿐이거나 읽을 글이 없다 → 격리유지(hotel).
방침 3 호텔·시설 안에 고유 이름을 가진 식당·바·카페·스파가 자기 CID 로 따로 등록돼 있다 → 그 이름의 행을 새 행 후보로 낸다(4번 절차). 호텔 행 자체는 방침 1·2로 따로 정한다. 고유 이름이 없으면 호텔 이름을 쓴다.
방침 4 호텔 페이지가 아닌 행(동네 소개 페이지, 구글 분류 글자가 식당인데 숙박 위젯만 붙은 곳) → 그대로.
방침 5 구글 페이지 자체가 호텔이 아니라 식당(호텔 위젯 없음 · Menu 탭 · 후기 칩이 음식 · 1인당 가격) → 주분류변경: 식당. 글도 다시 쓴다.
방침 6 요약·묘사의 업종과 페이지·후기의 업종이 완전히 다르다(철칙 12) → 삭제 · 확신 애매. 예) 요약은 "현지인 해산물 식당"인데 페이지·후기 칩이 전부 자전거 수리·타이어 → 삭제 후보. 실제 가게가 시장·유명 상점가·박물관급이면 주분류변경 + 글 새로 쓰기.
방침 7 식당 태그가 달린 몰·시장·탑·박물관·공원·전망대로 행 이름이 식당 상호가 아니다 → 식당태그제거(주분류는 그대로 또는 철칙 7). 안의 이름 있는 식당은 새 행 후보로 낸다. 예) 호수 공원 행에 식당 태그, 공원 안 별도 등록 카페가 있다 → 태그 제거 + 새 행 후보 1개.
방침 8 행 이름이 곧 먹고 마시는 곳(바·펍·비어 가든·카페·식사가 되는 공연장) → 식당태그유지. 예) 재즈 클럽인데 Menu 탭과 Dine-in 이 있고 후기 칩에 음식이 있다 → 유지.
방침 9 루프탑·옥상·전망대 · 이름에 식당 상호(레스토랑·바·카페 등)가 있다 → 식당 주분류 + 포토스팟 태그. 상호가 없다 → 포토스팟 주(먹고 마실 수 있으면 식당 태그).
방침 10 와이너리·샴페인 하우스 → 즐길거리(시음·견학). 이름에 식당이 든 와이너리 → 식당 주분류 + 즐길거리 태그. 도심 와인 바 → 식당. 포도밭 → 힐링. 와인 가게 → 쇼핑.
같은 가게가 이름만 달리 두 번 등록된 것(같은 주소·전화)은 후기 많은 쪽 하나만 새 행 후보로 내고 다른 하나는 reason 에 적는다.

5. 새 행 후보 만들기 — 호텔·시설 안에 이름 있는 식당이 있을 때
1) 구글 맵에서 그 이름을 검색해 열고 확인한다: 이름 · CID · 위도·경도 · 주소 · 후기 수 · 구글 분류 · 가격 · 영업 상태(영구·임시 폐업은 후보로 내지 않는다).
2) CID 읽는 법 = 주소창의 "!1s0x…:0x…" 에서 콜론 뒤 16진수를 10진수로 바꾼다(자바스크립트 BigInt("0x…").toString()). 호텔 페이지의 "At this place" 가게를 눌러 열면 주소창에 호텔 것과 가게 것이 함께 나오고, 가게 것은 두 번째 "!1s" 다.
3) 창고 중복 확인은 최종 검수 책임자가 CID 로 한다. 너는 CID 를 정확히 적는다.
4) 구글 맵에 별도 등록이 없으면 후보로 내지 않는다.
5) 가격은 철칙 8 로 채운다(머리줄 > 공식 > 검색).

6. 결과 서식 — 모두 JSON, 결과 폴더에 쓴다 (파일 이름 끝 {조번호} 는 네 조 번호)
read-proof-{조번호}.json = {"대명제": "한 줄 재진술", "철칙되받기": {"1": "자기 말 한 줄", ... "12": "..."}, "확인문제": {"Qn": "답", ...}}
verdict-{조번호}.json = 위 "결과"의 칸(cid · keep · reason · source · 페이지를 열었으면 doubt · evidence)을 모든 행에 쓴다. 추가편 범위 행은 거기에 아래 칸을 더 쓴다 — {"글_단서": "...", "검색": [{"질문": "...", "힌트": "..."}, ...], "맵검색": ["이름(주소 일치 여부)", ...] 또는 ["해당 없음: 식당 행"], "페이지": {"cid": "...", "끝까지스크롤": true, "안의가게": ["이름(분류·후기수)"], "후기최신": ["(시각) 요지 [숙박|전망|식사|스파]", ... 5개], "후기점수": {"숙박": 0, "전망": 0, "식사": 0, "스파": 0}, "후기주제": ["..."], "호텔위젯": true|false, "머리줄가격": "..." 또는 "없음", "영업상태": "..."}, "업종일치": {"요약업종": "...", "페이지업종": "...", "후기업종": "...", "일치": true|false}, "방침": "1~10 중 번호", "철칙": [번호들], "체험_한줄": "이 가격에 여기서 이 체험이 가능하다/불가능하다 + 근거", "처리": "...", "fix": {"seed_category": "...", "tags": [...], "remove_tags": [...]} 또는 {}, "짝확인": "분류·요약·묘사가 한 짝임을 한 줄로", "확신": "확실|애매", "가격": 숫자 또는 null, "가격근거": {"머리줄": "...", "공식": "...", "검색": "...", "채택": "..."}}
   keep 은 처리가 그대로·식당태그유지·격리유지이면 true, 식당태그제거·주분류변경·삭제이면 false 다. keep=false 의 reason 에는 맞는 값(분류·태그·가격·삭제 사유)을 적는다.
   페이지를 열지 않은 행은 "페이지": "안 엶: 로그로 확인" 으로 쓰고, 업종일치의 "페이지업종"·"후기업종"도 "안 엶" 으로 쓴다. 이것도 유효하다(빈 칸이 아니다).
new-rows-{조번호}.json = [{"이름": "...", "어느_안": "행 번호/이름", "cid": "...", "위도": 0, "경도": 0, "주소": "...", "후기수": 0, "구글분류": "...", "가격_유로": 0, "가격근거": {"머리줄": "...", "공식": "...", "검색": "...", "채택": "..."}, "영업상태": "..."}]  새 행 후보가 없으면 빈 목록 [] 로 쓴다.
빈 칸이 하나라도 있으면 그 줄은 무효다.

7. 끝내기 전 자가 점검 — 하나라도 아니오면 끝내지 않는다
□ read-proof-{조번호}.json 을 먼저 썼는가 □ 네 몫의 모든 행에 판정이 있고 추가편 범위 행은 근거 칸이 다 차 있는가 □ 연 행마다 의심 한 줄(doubt)이 있는가 □ 연 행은 끝까지 스크롤하고 후기를 최신 순으로 5개 읽었는가
□ 호텔·시설 행마다 안의 가게 찾기 세 번을 했는가 □ 호텔을 분류처럼 줄 세우지 않았는가 □ 구글 종류 글자 하나로 결론 내지 않았는가
□ 식당 가격이 채워졌고 머리줄 값이 있으면 머리줄 값을 썼는가 □ 후기 수·별점으로 거르지 않았는가 □ 분류와 글이 한 짝인가
□ "확실"마다 행의 칸이 로그나 연 페이지와 짝이 맞는가 □ 요약과 페이지 업종이 다른 행을 삭제 후보 + 애매로 올렸는가 □ DB 를 직접 쓰지 않았는가 □ 파일 3개를 결과 폴더에 썼는가

8. 금지
