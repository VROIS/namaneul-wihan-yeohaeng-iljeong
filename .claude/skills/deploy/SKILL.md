## 절차

### 1. 무엇을 해야 하는지 **먼저 판단** (건너뛰지 말 것)

```bash
node scripts/deploy-decide.mjs
```

이 도구가 마지막으로 구운 시점 이후 바뀐 파일을 보고 **스스로 정한다.**
**감으로 정하지 마라.** 이 도구의 답을 따른다.

| 답 | 뜻 | 무엇을 하나 |
|---|---|---|
| `ota` | 화면·글자·로직만 바뀜 | **2번** (무선 업데이트, 1~2분) |
| `build` | 새 부품·네이티브 설정이 바뀜 | **3번** (진짜 굽기 = `/build` 스킬) |
| `server-only` | 서버만 바뀜 | **4번** (Replit 안내만) |
| `none` | 폰에 넣을 게 없음 | 그렇다고 말씀드리고 끝 |

⚠️ `needsReplit: true` 이면 위 무엇이든 **4번을 함께** 안내한다.

### 2. 무선 업데이트 (대부분 이것)

⚠️ **미커밋이 있으면 먼저 사장님께 알리고 커밋 지시를 받는다**(§10).
커밋 안 된 코드를 폰에 보내면 저장소와 폰이 달라져 나중에 추적이 안 된다.

```bash
npx eas update --branch main --message "<무엇을 고쳤는지 한 줄>"
```

- 채널은 `eas.json` 의 모든 프로필이 `main` = **TestFlight 앱과 APK 둘 다** 이 업데이트를 받는다.
- 사장님은 **앱을 껐다 켜기만** 하시면 된다(다음 실행 때 적용).

### 3. 진짜 굽기 — `build` 일 때만

`/build` 스킬을 부른다. 거기에 버전 올리기·TestFlight·APK 바탕화면 다운로드까지 다 있다.
**여기서 그 절차를 다시 쓰지 마라**(§16 = 같은 것 두 벌 금지).

### 4. 서버가 바뀌었으면 — Replit

앱만 보내서는 반영되지 않는다. 사장님께 이렇게 안내한다:

> Replit 에서 **Republish** 눌러 주십시오. (서버가 바뀌어서 이것도 필요합니다)

`my-guide.replit.app` 은 autoscale = **Republish 해야만** 최신이 올라간다.

| 2 | 화면만 고쳤는데 굽기 | 무선 업데이트로 1~2분이면 끝날 일 |
| 3 | 새 부품 넣고 무선 업데이트만 | **절대 안 들어간다.** 앱이 그 부품을 못 찾아 죽는다 |
| 4 | 미커밋인 채로 폰에 보내기 | 저장소와 폰이 달라져 추적 불가 |
| 5 | 서버 바뀐 걸 알고도 Replit 안내 안 함 | 앱만 새것, 서버는 옛것 = 원인 못 찾는 오류 |

## 왜 무선 업데이트로 새 부품이 못 가나 (쉬운 말)

앱은 **껍데기(부품 상자)** 와 **속(자바스크립트)** 으로 되어 있다.
무선 업데이트는 **속만** 바꾼다. 부품 상자는 구울 때만 새로 짠다.

= 새 부품을 넣고 속만 보내면, 앱이 없는 부품을 찾다가 죽는다.
그래서 `package.json` 에 라이브러리가 추가되면 **반드시 구워야** 한다.

2026-07-31 애플 로그인이 그랬다 — `expo-apple-authentication` 이라는 새 부품이라 빌드가 필요했다.
반대로 같은 날 크레딧 안내 문구 고친 것은 **글자만** 바뀌어서 무선 업데이트로 충분했다.
